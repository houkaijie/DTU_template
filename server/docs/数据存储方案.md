# DTU配置平台 数据存储方案

## 一、存储分层架构

| 存储层 | 开发环境 | 生产环境 | 用途 |
|--------|---------|---------|------|
| 关系数据库 | SQLite (Node内置 `node:sqlite`) | MySQL 8.x | 用户、设备、分组、参数配置、操作日志 |
| 时序数据 | `device_heartbeats` 表 | InfluxDB / ClickHouse | 设备心跳、流量、信号等高频时序数据 |
| 缓存/会话 | SQLite 表 (`captcha_sessions`) + 内存 | Redis | 图形验证码、短信验证码、Token黑名单、设备在线状态 |
| 文件存储 | 本地磁盘 (`server/data/export`) | OSS / MinIO | 导出文件（设备列表CSV、配置JSON） |

## 二、ER 关系

```
┌─────────┐    1:N     ┌─────────┐    1:N     ┌─────────┐
│  users  │────────────│ devices │────────────│ groups  │
│ (账号)  │            │ (设备)  │            │ (分组)  │
└─────────┘            └────┬────┘            └────┬────┘
                            │ 1:N                  │ 1:N (config)
                     ┌──────┴──────┐        ┌──────┴──────┐
                     │device_heart-│        │operation_   │
                     │ beats(心跳) │        │logs(操作)   │
                     └─────────────┘        └─────────────┘

captcha_sessions (验证码会话, 独立表)
```

## 三、表结构说明

### 1. users 用户表
- `mobile` 唯一索引 — 登录账号（手机号）
- `role` — 0:普通用户 1:超级管理员（控制 /user/list 及设备跨用户操作权限）
- `password` — 生产环境建议 bcrypt 哈希（当前为明文便于演示，生产切换）

### 2. groups 分组表
- **`config` 字段是核心**: 存储完整设备参数配置 JSON（约 2KB），
  结构对应前端"参数配置"9 个 Tab：
  - `passon/plate/convert/reg/param_ver` — 基本参数（模式/前后缀/报文转换/注册包/参数版本号）
  - `uconf[2][7]` — 串口参数（波特率/数据位/停止位/校验/引脚/分帧超时）
  - `conf[6][N]` — 网络通道（HTTP/SOCKET/MQTT/ONENET/阿里云/百度云/腾讯云）
  - `cmds[2][N]` — 自动采集任务（时间+AT指令列表）
  - `upprot/dwprot` — 数据流模板
  - `gpio/gps/apn/tasks` — GPIO/GPS/APN/定时任务
- `param_ver` 每次保存自动 +1，DTU 设备通过 `GET /iot/api/config/:imei` 比对版本号决定是否拉取新配置
- `is_default=1` 为系统默认分组（不可删除/改名），新设备自动归属

### 3. devices 设备表
- `imei` 唯一 — DTU 设备身份标识（15位数字）
- `iccid/hadr/ver/csq` — 由设备心跳上报实时更新
- `online_time` — 最近心跳时间，在线判定 = now - online_time < 120s
- `group_id` — 设备所属分组（决定其参数配置）
- `user_id` — 设备所属账号（普通用户仅可见/操作自己的设备）

### 4. device_heartbeats 心跳时序表
- 每次设备心跳写入一条（含信号/版本/IP/流量）
- 索引: `(imei)`, `(created_at)`
- **生产环境迁移**: 该表写入量大且只追加，建议迁移至 InfluxDB
  （保留 90 天热数据，历史归档至冷存储）

### 5. operation_logs 操作日志表
- 记录所有敏感操作: `device.create/delete/transfer/changeGroup`、`group.update(配置下发)`、`user.changeRole` 等
- `detail` JSON 存操作详情，`ip` 记录来源
- 用于安全审计与故障回溯

### 6. captcha_sessions 验证码会话表
- uuid 主键，code 一次性使用，5 分钟过期
- **生产环境迁移**: 替换为 Redis `SETEX captcha:{uuid} 300 {code}`，
  配合验证码重放防护

## 四、关键设计决策

1. **配置即 JSON**: 设备参数配置以 JSON 字符串存于 groups.config，
   无需为每种云平台建表；结构灵活、与设备固件协议解耦。
   校验层保证 JSON 合法性，防止脏数据下发。

2. **读写分离策略**:
   - 热数据（设备状态/在线）→ 内存缓存 + 数据库落库
   - 时序数据（心跳）→ 追加写入，定期归档
   - 冷数据（操作日志）→ 长期保留，按月分区

3. **幂等设计**: IMEI 唯一约束 + 批量操作事务化（BEGIN/COMMIT/ROLLBACK），
   设备重复注册/重复上报不产生脏数据。

4. **安全**:
   - JWT 无状态鉴权（7天过期），请求头 X-Token
   - 图形验证码一次性 + 5分钟过期
   - 普通用户数据隔离（所有查询强制拼接 user_id 条件）
   - 管理员接口独立 admin 中间件
   - 密码生产环境切换 bcrypt

## 五、IoT 数据流

```
DTU设备 ──心跳/上报──▶ /iot/api/heartbeat ──▶ 更新 devices.online_time
                       /iot/api/report     ──▶ device_heartbeats 落库
                                            └─▶ mqtt-bridge 桥接到阿里云/ONENET等

DTU设备 ◀──配置下发── GET /iot/api/config/:imei ◀── groups.config (param_ver 比对)
```

## 六、MySQL 迁移说明

代码层已按 SQL 兼容风格编写（`schema.sql` 为 SQLite 方言）：
1. 安装 mysql2 依赖，替换 `server/db/index.js` 中连接初始化
2. `INTEGER PRIMARY KEY AUTOINCREMENT` → `BIGINT AUTO_INCREMENT`
3. `TEXT`/`DATETIME` 兼容，无需改动业务代码
4. 将 `device_heartbeats` 迁移到 InfluxDB，其余表直接建表
